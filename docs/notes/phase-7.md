# المرحلة 7 · تطبيق السائق (برق كابتن)

## ليش مبني هيك

### 1) السيرفر بيقرر الخطوة
ما في بالتطبيق «بعد الاستلام بييجي كذا». كل مرة بيرجع السيرفر `next_action`، والتطبيق بيعرض `label` تبعه. الفرع الوحيد:
- `action = deliver` → شاشة التسليم.
- `requires` فيها صورة → شاشة التصوير.
- `confirm` موجود → سؤال قبل الإرسال.

لو صاحب الـ API غيّر الخطوات بكرة، التطبيق بيمشي بدون تعديل.

### 2) الموقع: `LocationTracker`
- كل قراءة بتنحط بقائمة انتظار، وبتنشال منها بس لما الإرسال ينجح. فلو راح النت، النقاط ما بتضيع.
- بيبعت مش أسرع من `location_min_interval_seconds`، وأكتر إشي 100 نقطة بالطلب (`points[]`).
- لو السيرفر رفض دفعة بـ `validation_failed` بنشيلها، عشان ما توقف كل اللي وراها.
- قبل ما يصير متصل لازم نبعت موقع، لأن السيرفر بيرفض بدونه.
- الخدمة بالخلفية من `geolocator` نفسها (إشعار ثابت)، فما احتجنا حزمة جديدة.
- النقاط بالذاكرة: لو انسكر التطبيق بالكامل وقت انقطاع النت، بتضيع.
- قرار الفريق: السائق اللي عنده مهمة جارية بيضل موقعه يوصل حتى لو صار غير متصل، لأن الزبون لسا بيتابع الطلب. الخدمة بتوقف بعد التسليم أو الإلغاء. `DriverCubit` بيفحص `GET /driver/orders/current` كل `polling.tracking_seconds`، بـ `Timer` عادي مش `Poller`، لأن `Poller` بيوقف بالخلفية والإلغاء ممكن ييجي وقتها.

### 3) `DriverCubit` واحد لكل التطبيق
حالة «متصل» بتأثر على الشاشة الرئيسية والزر الوسط وخدمة الموقع، فهي بمكان واحد. لما تنتهي الجلسة أو يسجل خروج، الخدمة بتوقف.

### 4) التحديث بعد أي تغيير
`JobsRepository.changes` بيطلق بعد القبول والتسليم، والطلبات والأرباح والسجل بيسمعوه ويعيدوا التحميل.

### 5) صورة واحدة، رفع واحد
`ProofCubit` بيخدم شاشتي التصوير والتسليم. بيحفظ `upload_id` بعد الرفع، فلو السيرفر رفض الخطوة (بعيد عن المكان) و«حاول مرة أخرى» ما بنرفع الصورة مرتين. وأي إعادة تصوير بتمسحه.

### 6) خارج النطاق
قبل الإعادة بنبعت موقع جديد، لأن السيرفر بيقيس من آخر موقع عنده.

## مسار البيانات (قبول طلب)
`JobCard` ← `JobsCubit.accept` ← `ApiJobsRepository.accept` (مع `Idempotency-Key`) ← `ApiClient`
- نجح → `/task`، و `TaskCubit` بيجيب `GET /driver/orders/current`.
- `already_taken` → ملاحظة حمرا وتحديث القائمة.
- `cash_limit_reached` → شاشة حد النقد.

## أشياء لازم تعرفوها
- **رقم الدخول:** السائق بيدخل بـ `059…` مش `+970…`، عكس الزبون.
- **التجربة الحية:** رحلة طلب حقيقية (قبول، صورة، تسليم، سجل، أرباح) انجربت يدويًا ونجحت. خطأ البعد عن المكان لسا مش موثق بـ `openapi.json`، و `isTooFar` مبني على توقع. `test/live_job_test.dart` بيطبع القيم.
- **أشياء بالتصميم مخفية** لأن الـ API ما بيرجعها: عدّاد العرض، ساعات العمل، مكتب برق، +12%، عدد المهام، اسم المنطقة، اسم المتجر والأجرة بالسجل. التفاصيل بـ `API_NOTES.md`.
- **الأجرة ₪0.5** من بيانات السيرفر، والتصليح بلوحة التحكم مش بالتطبيق.
- **Firebase مش موصول** (زي تطبيق الزبون)، فالإشعارات الفورية ما بتوصل، بس قائمة الإشعارات شغالة.
- **شاشات النظام** (صيانة، بلا نت…) بدون `DesignOverlay` لأن تصاميمها فاتحة وخاصة بالزبون.
- **الاختبار الحي:** مرروا دخول السائق بـ `--dart-define` بس، وبعدها احذفوا `build/test_cache` لأن المترجم بيخزن القيم فيه.
